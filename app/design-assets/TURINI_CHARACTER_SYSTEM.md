# 투리니 캐릭터 조합 구조와 한계

작성 기준: 2026-09-19 · 자산팩 `Turini_Character_Core_Assets` + `Turini_Worn_Previews_v2`

---

## 1. 무엇을 무엇으로 그리는가

앱 안의 모든 투리니는 **`app/turini-avatar.tsx` 의 `TuriniAvatar` 하나**만 씁니다.
화면마다 이미지를 직접 불러오는 곳은 남아 있지 않습니다.

| 상황 | 그리는 방식 | 액세서리 반영 |
|---|---|---|
| `motion="idle"` (홈·마이페이지·꾸미기·로그인·포트폴리오 안내 등) | **레이어 리그** `turini-rig.tsx` | 모자·안경·목장식·가방 **전부 반영** |
| `thinking` / `celebrate` | **12프레임 스프라이트** + 프레임별 앵커 | 모자·안경·목장식 (가방 제외) |
| `correct` / `wrong` / `reading` | **12프레임 스프라이트** + 프레임별 앵커 | 모자·안경 (가슴 앞 팻말·책을 가리지 않도록 목장식·가방 제외) |
| 1회 재생(`correct`/`wrong`/`celebrate`)이 끝난 뒤 | 리그로 자동 복귀 | 가방까지 **전부 반영** |
| 꾸미기 목록 썸네일 / 한 아이템만 보는 미리보기 | 전달받은 **착용 완성본** `worn/*-worn.png` | 그 아이템 하나 (겹쳐 쓰지 않음) |
| 가방 탭 3/4 후면 · 뒷면 | 착용 완성본 + 턴어라운드 | 가방 |

## 2. 리그가 "떠 있지 않은" 이유

`character/rig/` 의 파츠는 모두 1200×1200 같은 캔버스에 그려져 있고,
`rig.json` 이 관절 좌표를 줍니다. 그래서 파츠를 그냥 겹치면 원래 캐릭터가 됩니다.

```
그림자 → 가방 본체 → [몸통 → 다리 → 어깨끈 → 팔] → [머리 → 목장식 → 안경 → 모자]
                                                    └ 머리 그룹: 같은 transform 을 함께 받음
```

- 모자·안경·목장식은 **머리 그룹의 자식**입니다. 고개가 기울면 같은 회전을 받으므로
  화면 위에 따로 떠 있을 수 없습니다. CSS 로 위치만 고정한 구조가 아닙니다.
- 가방 본체는 **몸통 레이어보다 아래**에 있습니다. 구조상 몸 앞으로 나올 수 없습니다.
- 어깨끈은 몸통 위·팔 아래에 그립니다. 팔이 흔들리면 끈이 팔 뒤로 들어갑니다.
- 부착 좌표(`SLOT_ANCHOR`)는 리그를 합성해 **눈·코·입·귀·목·어깨 픽셀 위치를 실제로 재서**
  잡았습니다. 아이템마다 다른 투명 여백은 `CONTENT_BOX` 로 보정해서, 칸이 아니라
  **그림 자체**를 기준점에 맞춥니다.

### 리그가 하는 움직임
숨쉬기(가슴만 부풂) · 고개 미세 기울임 · 좌우 팔 따로 흔들림 · 다리 미세 반동 ·
지면 그림자 호흡 · **3~6초 간격 불규칙 눈 깜박임**.
주기를 4.2s / 5.6s / 3.4s / 3.9s / 4.6s / 5.1s 로 다르게 둬서 기계처럼 맞아떨어지지 않습니다.

눈 깜박임용 머리 그림 2장(`turini-head-blink.png`, `turini-head-blink-half.png`)은
전달받은 `character/face/eyes_closed.png`·`eyes_half.png` 를 리그 머리에 맞춰
**이번 작업에서 파생 생성**한 자산입니다. 원본 자산은 그대로 두었습니다.

## 3. 애니메이션 위의 액세서리 — 어떻게 풀었나

### 3-1. 처음 판단이 틀렸습니다

처음에는 "고개가 3차원으로 돌아가서 정면 모자를 얹을 수 없다"고 적었는데,
12프레임을 전부 펼쳐 보니 **모든 프레임에서 얼굴이 정면을 봅니다.**
위치·크기·약간의 기울기만 바뀝니다. 그래서 프레임별 기준점만 있으면 됩니다.

### 3-2. 프레임별 기준점을 직접 만들었습니다

`public/assets/turini/animations/turini-frame-anchors.json`

```json
{ "cell": 256, "templateCenter": [129, 63],
  "frames": { "idle": [[129, 63, 1.0, 0], ...12개], ... } }
```

각 값은 `[가로중심, 세로중심, 배율, 기울기(도)]` 이고, idle 0번 프레임의 머리를
기준(1.0)으로 삼아 **템플릿 정합**(마스크 SSD, 배율 0.74~1.34 · 회전 ±18°)으로
72프레임 전부를 맞춰 구했습니다.

팻말이나 손이 머리를 가려 정합이 흔들린 프레임 6개(`correct` 4·6·8,
`celebrate` 6, `reading` 10·11)는 오차와 배율 이상치로 걸러 낸 뒤
앞뒤 프레임 값으로 메웠습니다. 반복 재생이라 순환으로 잇습니다.

화면에서는 이 값으로 액세서리 묶음 하나를 통째로 옮기고·키우고·기울입니다.
따라서 액세서리가 화면 위에 따로 떠 있지 않고 고개를 그대로 따라갑니다.

### 3-3. 기준점 표를 두 벌 두는 이유

리그 그림과 아틀라스 그림은 **머리·몸 비율이 서로 조금 다릅니다.**
(리그: 눈 폭 341/머리 폭 614, 아틀라스: 눈 폭 78/머리 폭 133)
같은 기준점을 그대로 쓰면 모자가 눈까지 내려옵니다. 그래서
`SLOT_ANCHOR`(리그용)와 `SPRITE_ANCHOR`(아틀라스용)를 따로 두고,
아틀라스 쪽은 idle 0번 프레임에서 이마 선·두 눈·목 시작점을 직접 재서 잡았습니다.

### 3-4. 아직 남은 제한

| 제한 | 이유 |
|---|---|
| 정답·오답·읽기 동작에서 **목 액세서리가 빠집니다** | 가슴 앞에 체크 팻말·X 팻말·책을 들고 있어 넥타이가 팻말을 가립니다. 팻말이 보이는 쪽을 택했습니다 |
| 모든 동작에서 **가방이 빠집니다** | 가방은 몸통에 붙는 물건인데 표는 머리만 추적합니다. 몸통까지 추적하려면 별도 앵커가 필요합니다 |
| **입 모양 변화가 없습니다** | 리그 머리에 눈·입이 그려져 있어 `face/*` 파츠를 얹으면 밑의 눈이 비칩니다 |
| **귀만 따로 반동**시킬 수 없습니다 | 귀가 머리 그림에 붙어 있습니다 |

### 3-5. 더 있으면 좋은 자산

| 파일 | 왜 필요한가 | 규격 |
|---|---|---|
| `turini-head-noface.png` | 눈·입이 빠진 머리 한 장. 있으면 **입 모양 변화**까지 만들 수 있습니다 | 1200×1200 투명 PNG, 지금 `turini-head.png` 와 같은 좌표계 |
| 가방 9종 `*-strap.png` | 지금 어깨끈은 가방 대표 색으로 그린 CSS 도형입니다 | 512×512 투명 PNG |
| `turini-ear_left/right.png` + 피벗 | 귀만 따로 움직이려면 필요합니다 | 1200×1200 |
| 몸통 프레임 앵커 | 애니메이션에도 가방을 붙이려면 필요합니다 | 72프레임 `{torso:{x,y,scale,rotation}}` |

## 4. 예외 처리

- 아이템 그림을 못 읽으면 그 아이템만 조용히 빠집니다 (깨진 아이콘 없음).
- 리그 파츠(몸통·머리)를 못 읽으면 **1단계 스프라이트 캐릭터로 통째로 대체**합니다.
- 아틀라스는 WebP → PNG 순으로 미리 받아 두고, 다 받기 전에는 프레임을 숨겨
  로딩 순간에 기본 캐릭터가 잠깐 보이는 일이 없습니다.
- 저장된 아이템 id 가 목록에 없거나 슬롯이 다르면 기본값으로 되돌립니다.
  옛 저장값의 `handProp`·`scene` 키는 무시합니다 (오류 없음).
- `prefers-reduced-motion` 에서는 리그·스프라이트 모두 멈추고 대표 프레임만 보여 줍니다.
